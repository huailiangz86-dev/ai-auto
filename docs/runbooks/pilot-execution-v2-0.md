# V2-P0 真实试点执行与放行 Runbook

**状态：** 当前执行基线。P1 开发暂停，直到本试点复盘通过。  
**目标：** 完成 10 家已入驻商户、50 名合格 Creator、30 个已冻结资金的 Campaign 与 100 条已发布内容，并以真实证据决定是否进入 V2-P1。

## 试点边界

- 仅使用真实、已审核的商户、Creator、订单及资金冻结；mock 数据只能用于本 runbook 的评估器和接口回归，不能计入试点目标。
- 每个 Campaign 必须在开始前完成资金冻结、实验组/对照组登记、基线期和观察期登记，并明确订单与 GMV 口径。
- P0 可采用人工发布和人工订单回传；没有可追溯证据时，不得宣称自动发布、核销、GMV、增量或 Creator 报酬已经验证。

## 固定统计口径

| 指标            | 口径                                                                                        |
| --------------- | ------------------------------------------------------------------------------------------- |
| 商户            | 已审核、状态正常，且至少有一个资金已冻结 Campaign 的商户                                    |
| Creator         | 已审核、状态正常，且在试点期接受过至少一个有效 Creator 任务的 Creator                       |
| 已冻结 Campaign | 存在冻结资金和对应预算分配的 Campaign；仅创建草稿不计入                                     |
| 已发布内容      | 有内容 ID、发布地址、发布时间和所属 Creator Task 的内容；同一内容只计一次                   |
| 订单            | 唯一、非测试、已验证/已结算的 merchant transaction；退款、取消和重复回调排除                |
| GMV             | 上述订单的 `transactionAmount` 合计（优惠前成交额）；实验/对照与基线/观察期必须使用同一口径 |

## 每个 Campaign 的启动清单

1. 商户、Creator 通过审核；Campaign 预算已冻结，资金来源、冻结时间与预算分配可查。
2. 登记实验单元和对照单元（地域或受众），并记录排除规则、基线期、观察期、订单口径、GMV 口径和协议版本。
3. 在观察期开始前冻结基线数据；之后只追加订单、核销、报酬和报告证据，不覆盖原始记录。
4. 任务、内容、追踪链接和券码逐项关联。每笔有效交易保留：同意版本/时间、领券记录、核销与商户交易号、Creator 归因、报酬记录和报告 ID。

## 每周复核

| 决策问题                          | 所需证据                                                     | 输出                                                      |
| --------------------------------- | ------------------------------------------------------------ | --------------------------------------------------------- |
| 核销与 Creator 报酬能否逐笔对账？ | 已验证核销 ID 与唯一报酬记录；金额、状态、任务/归因链路      | 已验证核销数、已对账报酬数、差异清单、对账率              |
| 增量订单/GMV 是否可解释？         | 每个 Campaign 的预登记实验/对照、基线/观察窗口及双重差分输入 | 已测 Campaign、可测量占比、增量订单、增量 GMV、假设与异常 |
| 商户是否验证价值？                | 同商户的第二个 Campaign 或同 Campaign 增加冻结预算           | 重复 Campaign 商户数/率、预算扩张商户数/率                |

同时记录有效 Creator 任务接受率：`已接受任务 ÷ 已邀请有效任务`。该指标用于诊断供给质量，不应用 mock 结果替代真实试点表现。

## 放行规则

进入 V2-P1 决策复盘前，必须同时满足：

1. `10 / 50 / 30 / 100` 全部达标；30 个 Campaign 均为真实资金冻结，100 条均为真实发布。
2. 每一笔已验证核销都有且只有一笔可追溯的 Creator 报酬记录；存在差异时不得放行。
3. 全部已冻结 Campaign 均已在观察期前预登记，并具有可解释的实验组/对照组增量证据；未测量不等于零增量。
4. 至少观察到一个商户的重复 Campaign 或预算扩张；同时在复盘中报告重复 Campaign 率、预算扩张率、有效任务接受率和可测量 Campaign 占比。

`apps/api/src/modules/pilot/pilot-release-gate.ts` 是上述规则的纯评估器；其测试以完整 mock 试点和三项关键缺口 mock 试点验证了放行边界。真实系统接入时，应把周度聚合结果作为其输入，并保留原始差异清单。
