# 商家内容与转化中心

## 目标

让商家在一个工作台完成达人内容的商业验收，并看清从内容分发到优惠券核销、佣金结算的完整链路。页面只展示汇总和脱敏交易凭证，不展示消费者身份信息。

## 核心产品规则

1. 优惠券是**活动的转化资产**，不是某一篇内容的附件。达人内容在支持的平台中通过“领取优惠”“专属链接”或二维码导流；用户领取后，优惠券进入用户券包。
2. 每个 Creator Task 自动生成不可猜测的 `trackingId`。外部链接携带该 ID；第一次有效触达建立归因时，系统把 Creator Task 写入归因快照。之后的核销从归因快照读取任务，不按达人 ID 反推。
3. 内容审核分层：AI/平台负责合规与风控，商家负责是否符合任务 brief、门店信息、优惠承诺和品牌调性。商家只能审核自己处于“待商家审核”的任务。
4. 佣金分两部分显示：
   - 内容基础报酬：达人接受邀约时锁定，验收/核验后进入 T+3 结算。
   - 核销佣金：仅对专属归因、已验证、未命中风控的核销计入；平台费、达人实得和状态分别显示。
5. 当前客户归因锁定周期沿用平台既有 365 天规则；但归因来源会固定到首次有效的 Creator Task，以便解释“是哪条内容引流”。

## 信息架构

在商家侧导航新增“内容与转化中心”，包含三个同级视图：

| 视图       | 商家要解决的问题                          | 主要动作                                                 |
| ---------- | ----------------------------------------- | -------------------------------------------------------- |
| 待审核内容 | 这份达人内容是否能代表品牌发布？          | 查看提交凭证、通过、打回并写明原因                       |
| 券与消费   | 券被谁领、在哪个门店用、转化质量如何？    | 按活动筛选，查看领券/核销/过期/GMV 与脱敏凭证            |
| 归因与佣金 | 哪个达人/任务带来核销，费用处于什么状态？ | 查看 Tracking ID、有效核销、基础报酬、核销佣金与结算状态 |

## 主界面

顶部只有一个活动筛选器和刷新操作，避免把全局筛选与表格操作混在一起。筛选后显示：

1. 内容状态：待商家审核、已通过待发布、已发布/追踪中。
2. 转化漏斗：内容曝光、内容点击、追踪领券、已验证核销、核销 GMV。
3. 成本与结算：优惠让利、待结算达人报酬、已确认佣金。
4. 任务表：达人、渠道、提交凭证、Tracking ID、领券、核销、GMV、预计/已确认报酬、状态和审核动作。

审核抽屉必须同时展示任务 brief、达人提交的草稿链接或说明、AI 内容证据、绑定的优惠券与专属 Tracking ID。商家操作“通过”后达人才能登记发布链接；“打回”时理由必填，达人回到创作状态。

## 数据闭环

```text
Creator Task（trackingId）
  -> 达人提交草稿 -> 商家验收 -> 发布内容
  -> 外部专属链接 / 二维码
  -> CustomerAttribution.creatorTaskId（首次有效触达快照）
  -> CustomerCoupon（领券）
  -> Redemption（已验证核销）
  -> Commission / CreatorTaskPayout（待结算、已结算或风控）
```

## API 边界

- `GET /merchant/conversion-center`：返回商家已授权范围内的汇总、券效果、任务及脱敏核销凭证。
- `POST /merchant/growth-tasks/creator-tasks/:id/review`：商家审核自己的已提交任务。
- `POST /creator/tasks/:id/submit`：达人可随提交动作写入草稿链接、说明与内容证据 ID。
- `POST /customer/attribution`：可携带 `trackingId`；服务端校验任务与达人、活动的一致性后固化任务归因，客户端不能直接伪造任务归因。

## 首版边界

- 不把外部平台的内容删除、违规判定伪装为实时结果；首版展示已接入的发布记录和平台回传指标。
- 归因数据仅用于核销、结算、反欺诈和商家效果统计；商家看到的交易凭证不含手机号、姓名或设备标识。
